# Open issues

What is still open after the device identification work: wrong or missing behavior, risks, and cleanups. [How it works](how-it-works.md) explains
how the scanner resolves and keeps a host's identity; this page assumes it.

Every item was checked against the code at the time of writing. Items that were fixed since the review rounds are not listed. Priority is a
judgment: **high** costs correctness or privacy now, **medium** should be done before the next larger change, **low** can wait or be accepted.

Examples use invented names (`lamp-kitchen`) and the documentation range `192.0.2.x`.

## Scanner and identification

| Issue                                                                                                                                                                                                                                                                                                                                                                                                                  | Why it matters                                                                                          | Direction                                                                                                                                                                                                                                                                      | Priority |
|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------|
| **Names and kinds flip between scans.** [IdentityResolver](../src/jvmMain/kotlin/com/bkahlert/netmon/identity/IdentityResolver.kt) resolves every scan from whatever the caches hold, and [ScanResult](../src/jvmMain/kotlin/com/bkahlert/netmon/scanner/ScanResult.kt) takes the scanned value whenever there is one. Nothing stores which source a field came from. Only a `Generic` kind falls back to the recorded one. | When an mDNS record drops out or returns, another source wins. A card changes label, icon and group.    | Keep each IP's last mDNS records for a TTL in [JmDNSServiceInfoCache](../src/jvmMain/kotlin/com/bkahlert/netmon/mdns/JmDNSServiceInfoCache.kt), or store each field's source rank in `Host` and replace a value only by one of equal or higher rank. Start with the TTL: it needs no change to the wire format. | high     |
| **A failed MAC-prefix refresh can stop the scanner at start.** [NmapMacPrefixesProvisioner](../src/jvmMain/kotlin/com/bkahlert/netmon/nmap/NmapMacPrefixesProvisioner.kt) calls `FileCache.update`, which downloads the table from `svn.nmap.org` when it is missing or older than 30 days. Nothing catches the failure, and `update` deletes the old file before it writes the new one. Read in the code, not reproduced. | A board that cannot reach the site at restart may not scan at all. A download that dies midway leaves a cut-off table with a fresh timestamp. | Download to a temporary file and move it into place. On failure, log a warning and keep the old table.                                                                                                                                                                         | high     |
| **Stale values survive the merge.** `ScanResult.mergeHost` keeps the recorded name, model, vendor, MAC, link and speed whenever the scan has none, and a recorded kind never goes back to `Generic`. The fallback is deliberate: it bridges mDNS gaps.                                                                                                                                                                                                                  | A value a rule no longer produces (an old placeholder name, an Apple code with its `@ECOLOR` suffix, a kind from a transient clue) stays until a scan yields a different value or the state file is deleted. After the rules changed, the Pi's state had to be reset by hand. | Stamp the state file with an identity version and drop the identity fields of older files on load. Or clean recorded names and models again on load.                                                                                                                            | medium   |
| **HomePod `_hap` outranks the accepted Apple code.** `MODEL_ORDER` ranks `PROTOCOL` above `APPLE_CODE`, and the `_hap` instance name is a `PROTOCOL` name. This follows the spec literally.                                                                                                                                                                                                                              | A HomePod shows the HomeKit accessory's name and model instead of the user's name and Apple's description. | Rank `APPLE_CODE` above `PROTOCOL` for the model once the code is accepted. Prefer the `_airplay` or `_companion-link` instance name over the `_hap` one.                                                                                                                         | low      |
| **A Fire TV running an AirPlay receiver app is named `AFTMM-36[AirPlay]`.** The emulator rule (`_airplay` carries `rmodel`) drops model, manufacturer and Apple code, but the `_airplay` instance name and `_googlecast` `fn` stay as `PROTOCOL` names and outrank the router host name. The emulator still gets speaker and television kind clues from the same records.                                                  | The card shows the app's instance name. The right kind wins today only because `_amzn-wplay` is listed first. | In [MdnsClues](../src/jvmMain/kotlin/com/bkahlert/netmon/identity/MdnsClues.kt), skip the `_airplay` instance name, `_googlecast` `fn` and their kinds when `emulator` is set.                                                                                                  | low      |
| **A DOWN host never gets a precise age.** A host that goes down gets `since = lastSeen`, up to `downAfter` (3 minutes) before the scanner decided. A host first met down gets `since = scanTime`. The age steps only exist for UP hosts.                                                                                                                                                                                | "DOWN since …" counts from the last sighting or the first scan, not from an observed event.               | Decide what `since` means for DOWN, then set it once and cover it in `ScanResultTest`. Add a down step to [OnlineAge](../src/commonMain/kotlin/com/bkahlert/netmon/OnlineAge.kt) only if it is wanted.                                                                          | low      |
| **Tuya `productKey` and Midea discovery are not read.** Both could name and classify the devices that only get a vendor and a kind from the OUI table today.                                                                                                                                                                                                                                                            | The router host names already cover the known devices, so the gain is small.                             | Only add them if router names turn out missing on a network without FRITZ!Box credentials.                                                                                                                                                                                     | low      |
| **The scan loop waits on more than nmap and the lockdown probe.** `MqttPublisher.publish` is Paho's synchronous QoS 1 publish and waits for the broker's ack, once per scan and once per changed host. The first worker start also downloads the MAC-prefix table (see above). | The rule that the scan never waits on the network is not true. A slow or stuck broker stalls scanning, and the DOWN decisions with it. | Publish from a separate thread with a bounded queue, or set a publish timeout. | medium |
| **The state file and the topics are keyed by the interface's own address, not the network.** The file is `scan.<interface>.<address>_<prefix>.json`, and the topic carries the same CIDR. | A new DHCP address starts with empty state (every `since` is reset), leaves the old file behind, and leaves the old retained scan on the broker, so the display can show both. | Key both by the network address (`InterfaceAddress.network`). Clear or ignore old files. | medium |
| **The state never forgets a host.** A recorded host stays (as DOWN) until another device takes its IP. | Devices with rotating private MACs add a card, and a record, each time. The file and every scan payload grow, and DOWN cards fill the small display. | Drop a DOWN host after a configurable time, and keep it out of the payload. | medium |
| **A sleep-proxied host keeps the proxy's vendor.** [NmapXml](../src/jvmMain/kotlin/com/bkahlert/netmon/nmap/NmapXml.kt) drops a MAC that several hosts share, but not the vendor read with it. | The vendor, its default kind, the Apple-code check and the lockdown probe then run on the proxy's OUI. | Clear the vendor together with the MAC. | low |
| **Lockdownd is probed for every host without a model and with an unknown or Apple vendor.** That includes private-MAC hosts, VMs and containers. A silent port costs up to 3 s, serially, once per 5 minutes per host. The probe cache is never evicted. | The probe runs in the scan loop and the cache grows with rotating MACs. | Probe only a host whose clues point to Apple, and evict expired entries. | low |

Smaller items, to batch:

- Vendor defaults in [OuiClues](../src/jvmMain/kotlin/com/bkahlert/netmon/identity/OuiClues.kt) are guesses: Amazon gives Speaker, HP gives Printer, LG gives Television. They only apply when nothing else knows the kind.
- Matching is loose. Several tokens of [NameTokens](../src/jvmMain/kotlin/com/bkahlert/netmon/identity/NameTokens.kt) are unanchored: `hue` matches any name that contains it, and `cam\b`, `printer` and `homepod` are as wide. `^Ring` matches any name that starts with it. A token's vendor outranks the OUI vendor, so a misfire also changes the vendor, the kind and the icon. [VendorNames](../src/jvmMain/kotlin/com/bkahlert/netmon/identity/VendorNames.kt) aliases match a bare prefix (`Appleton` becomes `Apple`, `Hewlett Packard Enterprise` becomes `HP`), and `AppleCodes.accepts` in [AppleCodes](../src/jvmMain/kotlin/com/bkahlert/netmon/identity/AppleCodes.kt) trusts any OUI vendor that starts with `Apple`.
- A blank OUI vendor becomes `Clue.Vendor("")`.
- `IdentityEnricher.toString` in [IdentityEnricher](../src/jvmMain/kotlin/com/bkahlert/netmon/identity/IdentityEnricher.kt) lists the sources but not the fallbacks.
- `HostServicesEnricher` takes the concrete `JmDNSServiceInfoCache`, where the clue sources take `MdnsLookup`.
- `LockdownProbe.Lookup` is nested in the probe, so [Application](../src/jvmMain/kotlin/com/bkahlert/netmon/Application.kt) needs a function adapter for it. Hoist it.
- `FritzBoxEndpoint.discover` returns a nullable `URI` and never returns `null`.

## Router (FRITZ!Box)

| Issue                                                                                                                                                                                                                                                                                                                                                                                  | Why it matters                                                                                                                                                                               | Direction                                                                                                                                                                                                               | Priority |
|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------|
| **Startup race: the first table refresh can run before mDNS found the box.** [FritzBoxHosts](../src/jvmMain/kotlin/com/bkahlert/netmon/router/FritzBoxHosts.kt) refreshes right after start. `FritzBoxEndpoint` then finds no `_tr064._tcp` record and falls back to `fritz.box`. On some networks that name resolves to a public address, so the connect times out. The next refresh, a minute later, works. | Every start logs one warning and shows no link or speed for the first minute. The recovery line is logged at INFO, so at the default level (`root` at WARN) the journal shows the failure but no recovery. | Retry sooner after a failed refresh, or wait for the first mDNS answer before the first refresh. Drop the `fritz.box` fallback, or log the recovery at WARN. The first one is the smallest change.                            | medium   |
| **`byIp` is always empty without router credentials.** Only `refresh` fills the by-IP table, and it does nothing without credentials. The per-MAC lookups are cached by MAC only. A host without a MAC gets no router name and no router MAC.                                                                                                                                                                                                       | A host nmap sees without a MAC (for example the scanner's own address) gets nothing from the router unless credentials are set.                                                                         | Accept and document it, or add an unauthenticated per-IP lookup.                                                                                                                                                       | low      |
| **A router speed behind a switch is the port's speed.** The router only knows the port, so a wired host behind a switch shows the uplink speed. A Wi-Fi rate is the negotiated rate and changes from scan to scan.                                                                                                                                                                       | The badge can claim `2.5 Gbit/s` for a device that cannot reach it, and the Wi-Fi figure jitters.                                                                                            | Say so in the README, or show no speed for a wired host. Smooth the Wi-Fi rate if the jitter bothers.                                                                                    | low      |
| **The scanner sends router credentials to any `_tr064._tcp` announcer.** With no `FRITZBOX_URL`, `FritzBoxEndpoint` trusts the first mDNS record. The call is plain HTTP with an MD5 digest.                                                                                                                                                                                              | A device on the LAN that advertises the record can collect a digest response. The LAN is trusted, so this was accepted.                                                                     | Require `FRITZBOX_URL`, or accept only a record at the default gateway.                                                                                                                                                 | low      |
| **An inactive entry matched by MAC still gives link and speed.** [RouterClues](../src/jvmMain/kotlin/com/bkahlert/netmon/identity/RouterClues.kt) checks `active` only for the by-IP match.                                                                                                                                                                                              | A sleeping device can show the link of its last connection.                                                                                                                                  | Emit link and speed only for an active entry.                                                                                                                                                                           | low      |

Smaller items:

- `Tr064Exception` messages carry up to 200 characters of the box's reply, and `FritzBoxHosts` logs them at WARN with only `sid=` masked. The same "host table not readable" warning also covers a failed per-MAC lookup.
- The host list is read with a 1 MB cap ([Tr064Client](../src/jvmMain/kotlin/com/bkahlert/netmon/router/Tr064Client.kt)). A network with several hundred hosts would fail every refresh.
- [DigestAuth](../src/jvmMain/kotlin/com/bkahlert/netmon/router/DigestAuth.kt) always computes MD5 and echoes the challenge's `algorithm`. It reads the first `WWW-Authenticate` header only.
- `FritzBoxHosts.lookupLoop` calls `pending.remove` twice on the failure path. `start` and `close` are `synchronized`, and `close` joins for up to 2 seconds.

## SSDP

| Issue                                                                                                                                                                                                                                                                                              | Why it matters                                                                                                                                      | Direction                                                                                                                                                                       | Priority |
|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------|
| **Description fetches block the receive thread.** [SsdpCache](../src/jvmMain/kotlin/com/bkahlert/netmon/ssdp/SsdpCache.kt) `offer` fetches on the thread that reads the socket, with a 3 s connect and 3 s read bound. The M-SEARCH at start and every 10 minutes is answered by many devices at once. | Datagrams that arrive during a fetch can be lost. A device is then unidentified until its next announcement. Not measured.                          | Fetch on a small bounded executor and let the receive thread only queue offers.                                                                                                  | medium   |
| **SSDP kinds rank below all mDNS kinds.** Both are `PROTOCOL`, and within one source the first clue wins. The sources are listed router, mDNS, SSDP.                                                                                                                                               | An `_airplay` or `_googlecast` record decides the kind even when the UPnP description knows better (a NAS, a printer).                              | Give SSDP its own `Source`, or list [SsdpClues](../src/jvmMain/kotlin/com/bkahlert/netmon/identity/SsdpClues.kt) before mDNS for the kind only.                                  | low      |
| **One sender can fill the location cache.** At most 512 locations are kept, and a new one is ignored while that many are fresh (30 minutes).                                                                                                                                                       | One chatty or spoofing device can stop SSDP identification of new devices for half an hour. Memory is bounded (about 4 MB). Router and mDNS still work. | A per-sender quota is only partial, since UDP source addresses can be spoofed on the LAN. Accepted so far.                                                                       | low      |
| **The same-host `LOCATION` rule leaves a second address without a description.** Only a location at the sender's own address is used. A NAS that answers from two addresses points both at one of them.                                                                                            | The second address gets no SSDP model and kind. The first one is identified.                                                                        | File the description under the location's IP, and allow only private, non-loopback address literals.                                                                             | low      |
| **`Entry.location` is stored and never read.** The comment says it stops a failing location from a reused IP from renewing an entry.                                                                                                                                                               | The protection is not there. A transient fetch failure can leave a device unidentified until its next announcement.                                 | Use the field in `offer`, or remove it and the comment.                                                                                                                          | low      |
| **The model prefers `modelNumber`.** For a FRITZ!Box it is a build tag such as `<number>avm`, not a product name.                                                                                                                                                                                  | The router card shows the tag.                                                                                                                      | Prefer `modelName` when the number is not a catalog-like token, or map known tags.                                                                                              | low      |
| **Any `ssdp:byebye` removes the sender's entry.** `offer` removes by IP, whatever `USN` or location the message names. | A device that says goodbye for one sub-service loses its description until the next announcement. | Remove only an entry whose location the message names. | low |

Smaller items:

- `CACHE-CONTROL: max-age` is parsed by `SsdpMessage.maxAge` and ignored. The TTL is a fixed 30 minutes.
- SSDP is IPv4 only. A location with an IPv6 zone id is dropped.
- A malformed description makes the JDK print `[Fatal Error]` to stderr, because [SecureXml](../src/jvmMain/kotlin/com/bkahlert/netmon/xml/SecureXml.kt) sets no error reporter. A `deviceList` before the fields, or a field with child elements, drops the whole description ([DeviceDescription](../src/jvmMain/kotlin/com/bkahlert/netmon/ssdp/DeviceDescription.kt)).
- The scanner binds port 1900 on the wildcard address with `SO_REUSEADDR`, one socket per interface. Sharing the port with another listener has not been tried: no other service listened on the Pi. On a board with several networks a socket may receive another interface's datagrams.

## mDNS

| Issue                                                                                                                                                                                                                       | Why it matters                                                                                              | Direction                                                                                                                  | Priority |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------|----------|
| **The mDNS cache is empty after a start.** JmDNS fills it during the first minutes. Without a stored state (a new interface, a reset), the first scan names far fewer hosts than the third (29 of 46 in one trial).        | A fresh install looks bare for a few minutes. The merge hides this on a board that keeps its state.        | Skip identity in the first scan or publish it only after a warm-up. The TTL for mDNS records from the first item above helps. | low      |
| **A TXT-only record never reaches the clues.** [JmDNSServiceInfoCache](../src/jvmMain/kotlin/com/bkahlert/netmon/mdns/JmDNSServiceInfoCache.kt) links a service to an IP only through its SRV target. `MdnsClues` was written not to need an SRV. | A device that answers with TXT only (a `_device-info` record) can lose its model. The Pis' records carry an SRV, so they work. | Map a service without SRV by the addresses JmDNS resolved for it, and add a test. | low |

Smaller items:

- `MdnsClues.Records` reads only the first record of an application, from an unordered set, so a host with two `_airplay` instances gives either. TXT keys are looked up case-sensitively, though DNS-SD keys are not.
- The emulator test differs between `MdnsClues` (first `_airplay` record) and `SsdpClues` (any). Move it to one place.
- The cache has no size cap: a service stays until its goodbye. It also has no test of its own, and none covers `services(application)`.
